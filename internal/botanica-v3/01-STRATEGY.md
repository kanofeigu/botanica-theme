## 决策 1：底座 → **Skeleton + theme-blocks 架构**（无悬念，规则决定）

这已经不是"偏好选择"，而是规则强制：

- **Skeleton 是唯一被批准的底座。** `shopify theme init` 默认就是克隆 Skeleton。
- **Dawn / Horizon 派生主题一律不合格。** 所以：
  - ❌ 不能在你现有 Dawn 版上加强（=继续违规，且大概率二次被拒 + 逼近封号）。
  - ❌ 不能用 Horizon 作底座（虽是新旗舰，但官方 README 明令禁止作 Theme Store 底座）。
  - ✅ **用 Skeleton 作底座，自己实现 theme-blocks 架构**（把 Horizon 当架构"参考"只读，不抄代码）。

**为什么不是"改 Dawn 更快"**：你只剩 2 次提交机会。在违规底座上提交=必拒+逼近 90 天封禁。唯一安全路径是 Skeleton 重建。

**给 DeepSeek 的硬约束**：所有 section/snippet/JS 必须是原创代码；可以把 Dawn 的 main-product block 结构当**行为参考**，但**不能 ship Dawn 的任何 component-*.css / 原生件 / JS 模块**。

## 决策 2：定位 → **多用途精品主题 + 植物旗舰 demo**（强烈推荐）

> 你的原计划是"纯植物百科主题"。我的建议是**转向"多用途 + 植物旗舰 demo"**。理由是硬市场数据：

### 市场数据
| 信号 | 数据 | 含义 |
|------|------|------|
| 垂直 vs 多用途销量 | 植物/园艺主题 ~40–100 销量（Botanika ~39、BioEarth ~41）；多用途 Ella ~26,700 | 垂直主题天花板极低 |
| 下架红线 | **滚动 3 个月卖不到 25 单就下架** | 纯植物主题有跌破风险 |
| 头部主题预设 | Prestige/Impulse 3 套、Be Yours 5 套，各服务不同行业 | 灵活性=生存与增长的双重要求 |
| 审核"唯一性" | 要求服务"specific merchant type"但不要求"单一垂直" | 多用途+强主题 demo 完全合规 |

### 推荐做法
- **主题本身是灵活的多用途精品**（强排版系统 + 可重组 block + 无代码定制）。
- **首发旗舰 demo = 植物店**（你已有的 editorial/植物百科美学，正好做最惊艳的那个 demo）。
- **再配 2–4 个相邻行业预设**（每个一套 demo + 行业标签），例如：
  1. **Botanical / 植物**（旗舰，editorial 奶油+sage）
  2. **Home & Decor / 家居软装**（更中性、留白、建筑感）
  3. **Wellness / Apothecary / 护肤药妆**（terracotta 暖调、有机感）
  4. **Artisan / Handmade / 手作**（暖纸质、复古标本感）

这样：①买家池扩大几十倍 ②避开 25 单下架线 ③多个差异化预设本身就是"设计 sophistication"的强信号，直接打中拒你的那道门。

> 如果你坚持"纯植物"：可以，但请明确知道天花板和下架风险。我会照你的选择调整 `02-PLAN.md`。**默认我按"多用途+植物旗舰"来写计划。**

## 决策 3：渠道 → Theme Store 主攻，ThemeForest 作对冲（可选）

- **主攻 Shopify Theme Store**（你的目标）：分成 85/15（对作者有利）、有 Shopify 流量与背书，但门槛高、要 Partner 申请 + 支持承诺 + 2 次机会风险。
- **可选对冲 ThemeForest / 自分发**：允许 Dawn 派生、上手快、能更早拿到第一笔收入和作品集；但无 Shopify 背书、分成差、需自己引流。
- **建议**：先全力打磨 Skeleton 版冲 Theme Store。**若想更早回血/降低单一渠道风险**，可以把"被否的 Dawn v1 适度完善后挂 ThemeForest"作为副线——两条线代码库不同，互不冲突。（这条是可选项，看你精力。）

## 决策 5：预设数量 → **3–5 个真正不同的预设**

- 对标头部（3–5 个）。**不是 5 个换色**，而是每个预设在**配色 + 字体比例 + section 构图**三个维度都明显不同。
- 每个预设：①写进 `settings_data.json` 的 `presets`（≤5、文件 ≤1.5MB）②一套匹配的真实 demo store ③`/listings/<preset>/`（如需 section-group 覆盖）④独立 listing 截图。
- 建议首发 **3 个**（植物 + 家居 + 护肤药妆），稳扎稳打；过审后再加。

## 决策 6：风险管理（你只剩 2 次机会）

这是最重要的一条软约束：

1. **绝不在 Dawn 版上再提交**——=必拒 + 逼近封号。
2. **一次性做到位再提交**——宁可慢，不可赌。提交前跑完 `02-PLAN.md` 的 5 阶段自审清单。
3. **提交前用邮件渠道**就 reviewer 反馈先沟通（可降低盲提风险）。
4. **基础设施先行**：文档站 + 支持表单（help-desk/CRM）必须在提交前上线，不是提交时才补。
